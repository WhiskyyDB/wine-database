# WineDB Data Dictionary

This document describes every WineDB table and column (`samples/` and `winedb.sqlite`): its type, its constraints, and how its values are made in the full snapshot (edition 2026.09).

**How the full snapshot is built (edition 2026.09).** No value is fetched from an external source at build time; every input is a file in the build repository.
- **3,611 of the 3,675 vintage rows (98.3%) are generated by a formula** from 113 hand-entered wine records. Each of those wines gets the same fixed grid of 32 years (1989–2023, without 1991–1993), whether or not the wine was made that year.
- **59 vintage rows were entered by hand**, each with a producer URL cited for the row. These are the rows of the free sample. The URLs were not fetched or re-checked.
- **5 vintage rows** come from a hand-typed list of product records.
- The reference tables (`wineries`, `wines`, `appellations`, `grape_varieties`) were entered by hand. 4 producers and 6 wines appear twice under accent variants (for example "Chateau Margaux" and "Château Margaux"), and 13 vintages appear twice with different values.

The free sample (`samples/`) holds only the 59 hand-entered vintage rows. Its `vintages.csv` has 11 of the 17 columns below (no `residual_sugar_g_l`, `acidity_g_l`, `organic_certification`, `source_id`, `source_type` or `source_name`), its `wineries.csv` has 6 of 9, and it ships no `data_sources.csv` (the SQLite preview has a `data_sources` table with one entry per vintage row).

---

## 1. `appellations.csv` (`appellations`)
Appellations (geographical indications), entered by hand. No source is recorded for them.

| Column | Data Type | Nullable | Description / Constraint |
| :--- | :--- | :--- | :--- |
| `appellation_id` | Integer / PK | No | Unique auto-incrementing identifier |
| `name` | String | No | Appellation name as entered (e.g., `Napa Valley`, `Pauillac`) |
| `country` | String | No | Country name |
| `classification` | String | Yes | Class label as entered. In the full snapshot it mixes legal schemes (`AOC`, `DOCG`, `AVA`) with château classifications (`AOC - First Growth`), a Wachau category (`Smaragd`) and a private association tier (`VDP Grosse Lage`) |
| `parent_region` | String | Yes | Broader region as entered (e.g., `California`, `Bordeaux`) |

---

## 2. `wineries.csv` (`wineries`)
Wine producers and estates, entered by hand.

| Column | Data Type | Nullable | Description / Constraint |
| :--- | :--- | :--- | :--- |
| `winery_id` | Integer / PK | No | Unique producer identifier |
| `name` | String | No | Producer name |
| `country` | String | No | Country as entered (`Unknown` on 4 rows of the full snapshot) |
| `region` | String | Yes | Wine region as entered |
| `founded_year` | Integer | Yes | Founding year as entered, with no source (must be between `1000` and `2100`) |
| `source_id` | Integer / FK | Yes | Foreign key to `data_sources.source_id` |
| `source_type` | String | Yes | Label copied from the `data_sources` entry |
| `source_name` | String | Yes | Label copied from the `data_sources` entry |
| `source_url` | String | Yes | URL copied from the `data_sources` entry. In the full snapshot, 68 rows carry a URL built from a pattern, 10 a Wikidata ID that points to an unrelated item or to none, 4 an Open Food Facts URL, and the rest the URL cited on a hand-entered row. None of them was checked |

---

## 3. `wines.csv` (`wines`)
Individual wines (cuvees), entered by hand.

| Column | Data Type | Nullable | Description / Constraint |
| :--- | :--- | :--- | :--- |
| `wine_id` | Integer / PK | No | Unique wine identifier |
| `winery_name` | String | No | Name of producing winery (FK `wineries.name`) |
| `name` | String | No | Wine name (e.g., `Insignia`, `Hillside Select`); some names carry a year |
| `wine_type` | String | No | Style as entered (`red`, `white`, ...). On the 7 wines from the hand-typed product list it was guessed from the name |
| `appellation_name`| String | Yes | Appellation as entered (FK `appellations.name`) |

---

## 4. `vintages.csv` (`vintages` / `wine_vintages`)
One row per wine and year.

| Column | Data Type | Nullable | Description / Constraint |
| :--- | :--- | :--- | :--- |
| `vintage_id` | Integer / PK | No | Unique row identifier |
| `winery_name` | String | No | Name of producing winery |
| `wine_name` | String | No | Wine name |
| `vintage_year` | Integer | No | Vintage year. On generated rows, a year from the fixed 32-year grid (1989–2023, without 1991–1993), whether or not the wine was made that year |
| `abv_percent` | Float | Yes | Alcohol by volume (`0.0 < value <= 25.0`). On generated rows, the wine's hand-entered base value plus or minus 0.2 in a fixed cycle |
| `bottle_volume_ml`| Integer | No | Bottle volume in ml. `750` on every row (a default, not a recorded format) |
| `aging_regime` | String | Yes | Cask / barrel maturation, as entered. On generated rows, one value per wine, the same in every year |
| `production_cases`| Integer | Yes | Cases produced (`>= 0`). Filled only on the 59 hand-entered rows |
| `release_price_usd`| Float | Yes | Release price in USD (`>= 0`), as entered. On generated rows, one value per wine, the same in every year from 1989 to 2023 |
| `valuation_index_usd`| Float | Yes | **A modelled index, not an observed price.** On the 3,611 generated rows it is computed from the wine's hand-entered base price and the year: `round(base_price × (1 + (2024 − year) × 0.038))`. One hand-entered row carries a hand-typed value. No value comes from an observed sale. Empty on every row of the free sample |
| `residual_sugar_g_l`| Float | Yes | Residual sugar in g/L (`>= 0.0`). One hand-entered value per wine, copied to every vintage of that wine (1,281 rows, 34.9%). No laboratory source |
| `acidity_g_l` | Float | Yes | Acidity in g/L (`>= 0.0`). One hand-entered value per wine, copied to every vintage of that wine (1,281 rows). No laboratory source. There is no pH or titratable-acidity column |
| `organic_certification`| String | Yes | Free text entered per wine (e.g. `Agroforestry / HVE 3`), copied to every vintage of that wine (1,281 rows). Not checked against any certifier register |
| `source_id` | Integer / FK | Yes | Foreign key to `data_sources.source_id` |
| `source_type` | String | Yes | Label copied from the `data_sources` entry: `tech_sheet` on generated and hand-entered rows, `openfoodfacts_api` on 5 rows |
| `source_name` | String | Yes | Label copied from the `data_sources` entry (e.g. `<winery> Technical Archives` on generated rows) |
| `source_url` | String | Yes | URL copied from the `data_sources` entry. On generated rows, built from a URL pattern plus the year and never fetched (the ones tested return "not found"). On hand-entered rows, the producer URL cited for the row, not re-checked. On 5 rows, an Open Food Facts URL for a barcode that does not exist there |

---

## 5. `blends.csv` (`vintage_blends`)
Grape varieties and their shares per vintage row.

| Column | Data Type | Nullable | Description / Constraint |
| :--- | :--- | :--- | :--- |
| `vintage_id` | Integer / FK | No | Target vintage identifier |
| `winery_name` | String | No | Producer name |
| `wine_name` | String | No | Wine name |
| `vintage_year` | Integer | No | Vintage year |
| `variety_name` | String | No | Grape variety as entered (`Cabernet Sauvignon`, `Merlot`, etc.) |
| `percent` | Float | No | Share of the variety (`0.0 < value <= 100.0`). Triggers `trg_check_blend_sum_insert` and `trg_check_blend_sum_update` abort any insert or update that makes a vintage's sum exceed `100.001`. On generated rows, the wine's hand-entered base blend with the first two varieties moved by one point, depending on whether the year is odd or even; the other varieties are copied |

---

## 6. `tasting_profiles.csv` (`tasting_profiles`)
Tasting keywords per vintage row.

| Column | Data Type | Nullable | Description / Constraint |
| :--- | :--- | :--- | :--- |
| `vintage_id` | Integer / FK | No | Target vintage identifier |
| `winery_name` | String | No | Producer name |
| `wine_name` | String | No | Wine name |
| `vintage_year` | Integer | No | Vintage year |
| `descriptor` | String | No | Tasting keyword as entered (`Black currant`, `Graphite`, `Vanilla`, etc.). On generated rows, the wine's fixed list repeated on every vintage, not mapped to a controlled vocabulary |

---

## 7. `data_sources.csv` (`data_sources`)
Entries referenced by `source_id` on `vintages` and `wineries` (`wines`, `blends` and `tasting_profiles` have no source column). In edition 2026.09 these entries do not record fetched sources; see each column.

| Column | Data Type | Nullable | Description / Constraint |
| :--- | :--- | :--- | :--- |
| `source_id` | Integer / PK | No | Unique entry identifier |
| `source_type` | String | No | Label: `tech_sheet` (3,675 entries, mostly URLs built from a pattern), `wikidata_sparql` (10; the IDs point to unrelated Wikidata items or to none), `openfoodfacts_api` (7; the barcodes do not exist in Open Food Facts), `saq_lcbo_monopoly` (40), `livex_benchmark` (8) and `ttb_cola` (6). The last three are hand-typed entries that no row references |
| `source_name` | String | No | Name label |
| `source_url_or_id`| String | No | URL or ID as recorded. 198 URLs appear more than once |
| `retrieved_at` | Timestamp | Yes | Filled on 59 of the 3,746 entries, with the time of the build, not of a retrieval |
| `raw_payload` | Text | Yes | On 59 entries, the hand-entered seed row itself; on 6, hand-typed text labelled as OCR extracts; empty elsewhere |

There is no licence column.
